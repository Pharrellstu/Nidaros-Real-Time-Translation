TODO – Live Auto-Captions POC for Wowza + Vosk (C#)

Goal
- Capture audio from the Wowza live stream, transcribe Dutch speech to text in near real-time, package as captions, and make them available to players as a selectable subtitle track.

High-level approach (POC-first, production-capable later)
1) Ingest audio from the live stream with low friction (preferred: RTSP from Wowza; fallback: HLS audio via ffmpeg, higher latency but simpler).
2) Transcribe in real time using Vosk .NET with a Dutch model (streaming recognizer, partial + final results).
3) Package as WebVTT subtitles segmented for HLS (rolling window). Serve a subtitle media playlist (.m3u8) and .vtt segments from our .NET service.
4) Expose a composite master playlist that mirrors Wowza’s master but adds an EXT-X-MEDIA subtitles group pointing to our subtitle playlist, so standard HLS players can select captions without modifying Wowza.
5) Deliver a simple test player page (hls.js) that uses our composite master playlist and verifies captions end-to-end.

Why this path
- Doesn’t require custom Wowza Java modules initially.
- Works with standard HLS clients and keeps Wowza container untouched.
- Lets us iterate on ASR, segmentation, and UX independently.

Key decisions (current)
- Protocol in: RTSP preferred (lower latency, continuous), HLS fallback OK for POC.
- ASR: Vosk .NET (NuGet: Vosk), Dutch model (e.g., vosk-model-small-nl-0.22; swap later for accuracy/size tradeoff).
- Packaging: HLS WebVTT sidecar (subtitle media playlist + .vtt segments). Composite master playlist generated by our API.
- Hosting: .NET service (Kestrel) serves subtitle playlists/segments and composite master.
- Timebase: Wall-clock based segmenter; align cue times to segment boundaries (2–4s target duration), rolling window size ~ 6 segments.

Architecture sketch
- NidarosRTT.Captions (new Worker or HostedService in API):
  - Input: stream URL (rtsp:// or http(s)://…m3u8), ffmpeg process outputs 16kHz mono PCM via pipe.
  - ASR: Vosk recognizer (streaming), emits partial/final transcripts with timestamps.
  - Segmenter/Packager: buffers words into cues, rolls .vtt segment files, updates .m3u8.
- NidarosRTT.API:
  - Endpoints to serve: /captions/{stream}/subtitles.m3u8, /captions/{stream}/seg-{n}.vtt
  - Endpoint to proxy & compose master playlist from Wowza, adding EXT-X-MEDIA subtitles (name/id = "nl-vosk").
  - Simple test player page.
- NidarosRTT.Core: models (TranscriptWord, Cue, Segment), interfaces (IAudioSource, ITranscriber, ISubtitlePackager).
- NidarosRTT.Infrastructure: ffmpeg runner, vosk wrapper, HLS packager, playlist composer.

Assumptions
- HLS playback is acceptable for the POC, small added latency is fine.
- Vosk Dutch model is allowed and can be stored/downloaded locally (~50–160MB).
- We can point to a stable stream URL from Wowza (RTSP or HLS).

Acceptance criteria
- When pointing the service at a live Dutch audio stream, a player using our composed master playlist shows a "Dutch (Vosk)" subtitle track with rolling captions in near real-time.
- If the stream restarts, the service reconnects and resumes subtitle generation without manual intervention.

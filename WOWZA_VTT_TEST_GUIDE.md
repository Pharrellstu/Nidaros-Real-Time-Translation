# Wowza VTT Integration Test Guide

## What Changed

We've now configured a **shared Docker volume** between the `api-service` (caption generator) and `wowza-trial` (streaming server) so that Wowza can serve the VTT files.

### Volume Configuration
```yaml
api-service:
  volumes:
    - shared_content:/shared_content
  environment:
    - VTT_OUTPUT_PATH=/shared_content/vtt

wowza-trial:
  volumes:
    - shared_content:/usr/local/WowzaStreamingEngine/content

volumes:
  shared_content:
    driver: local
```

### Directory Structure
```
shared_content/              (Docker volume)
└── vtt/
    └── OBSstream.vtt       (Generated by api-service)

This maps to:
- api-service:  /shared_content/vtt/OBSstream.vtt
- wowza-trial:  /usr/local/WowzaStreamingEngine/content/vtt/OBSstream.vtt
```

## Testing Steps

### 1. Rebuild and Restart Services

```fish
cd /home/pop/Documents/gdrive/nhlStenden/Y2-P2/Project/Nidaros-Real-Time-Translation
docker-compose down
docker-compose up --build -d
```

### 2. Verify Volume Mounting

Check that both containers see the shared volume:

```fish
# Check api-service can write to shared volume
docker exec nidaros-real-time-translation-api-service-1 ls -la /shared_content/vtt/

# Check wowza can read from shared volume
docker exec nidaros-real-time-translation-wowza-trial-1 ls -la /usr/local/WowzaStreamingEngine/content/vtt/
```

Both should show the same `OBSstream.vtt` file!

### 3. Start OBS Streaming

Start streaming to generate VTT content (as before).

### 4. Access VTT File via Wowza HTTP

Wowza serves content from its `/content` directory via HTTP. Try accessing:

```
http://localhost:1935/vtt/OBSstream.vtt
```

Or with curl:
```fish
curl http://localhost:1935/vtt/OBSstream.vtt
```

**Expected Output:**
```
WEBVTT

00:00:00.500 --> 00:00:04.200
Hello world, this is a test.

00:00:06.300 --> 00:00:08.800
How are you doing today?
```

### 5. Test with HLS Player

If Wowza is configured for HLS, you can reference the VTT in the player:

```html
<video id="player" controls>
  <source src="http://localhost:1935/live/OBSstream/playlist.m3u8" type="application/x-mpegURL">
  <track kind="subtitles" src="http://localhost:1935/vtt/OBSstream.vtt" srclang="nl" label="Dutch">
</video>
```

## Troubleshooting

### Volume not mounted
**Symptom:** `ls: /shared_content: No such file or directory`

**Solution:**
```fish
docker-compose down -v  # Remove old volumes
docker-compose up --build -d
```

### Permission denied writing VTT
**Symptom:** `Access to the path '/shared_content/vtt' is denied`

**Solution:** Verify Dockerfile creates directory with `chmod 777`:
```dockerfile
RUN mkdir -p /shared_content/vtt && chmod 777 /shared_content/vtt
```

### Wowza can't read VTT file
**Symptom:** HTTP 404 when accessing `http://localhost:1935/vtt/OBSstream.vtt`

**Solution:** Check Wowza logs:
```fish
docker logs nidaros-real-time-translation-wowza-trial-1 | grep -i vtt
```

Verify Wowza content path:
```fish
docker exec nidaros-real-time-translation-wowza-trial-1 cat /usr/local/WowzaStreamingEngine/content/vtt/OBSstream.vtt
```

### VTT file not updating
**Symptom:** Old content in VTT, new captions not appearing

**Cause:** VTT file is opened once and cached by Wowza

**Solution (for testing):** Restart Wowza or use a different stream name
